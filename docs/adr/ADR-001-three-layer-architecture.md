# ADR-001: 三层问题架构（Three-Layer Question Architecture）

**日期**: 2026-05-08  
**状态**: 已接受  
**决策者**: 项目作者

---

## 背景

需要设计一个既通用（适用于所有任务类型）又精准（针对具体任务有足够鉴别力）的评估问题集合架构。

两个极端方案各有问题：
- **纯静态问题集**：可复用但缺乏任务特异性，对细粒度质量差异鉴别力弱
- **纯动态生成**：每次都完全依赖 LLM 生成，成本高且一致性差

---

## 决策

采用三层架构：

1. **Layer 1 - Baseline（4题，始终存在）**：任务无关的通用质量门槛（意图匹配、可交付性、质量基线、可操作性）
2. **Layer 2 - Dynamic（4-10题，LLM生成）**：由 `CriteriaGenerator` 根据任务描述动态生成的特定评估问题
3. **Layer 3 - Override（0-6题，按输出类型）**：当输出类型为代码/文件/表格时，替换部分通用问题

权重分配：Layer 1 占 40%，Layer 2 占 40%，Layer 3 占 20%。

---

## 后果

**正面**：
- Baseline 层保证最低评估质量，即使 LLM 生成失败也有兜底
- Dynamic 层提供任务敏感性，不同任务有差异化评估
- Override 层针对代码/文件类型避免"文本质量偏见"（代码不需要引用文献）

**负面/风险**：
- P0 发现 Mid 候选有时得分 > High（T004-M=0.918 > T004-H=0.860），说明 Layer 2 可能过度强调"结构完整性"而非"内容深度"
- 需要持续迭代 Dynamic 生成的 prompt，避免生成无区分度的问题

**后续动作**：
- P2 完成后分析 per-layer 的 ρ 贡献，验证三层设计是否都有独立价值
- 如果 Layer 2 质量不稳定，考虑引入人工审核的问题模板库作为补充
